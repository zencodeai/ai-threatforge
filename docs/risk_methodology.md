# Risk Methodology v0.1

This document defines the explainable risk model used in Phase 4 (`#10` + `#11`).

## Objectives
- convert structured threats into prioritized risk records
- keep risk scoring deterministic and reproducible
- provide analyst-readable explanations with explicit top drivers

## Inputs
- threat artifacts generated by `analysis/threat_outputs.py`
- threat metadata:
  - severity hint
  - target type
  - framework mappings
  - rule/evidence context

## Risk factors
Each risk is scored with six normalized factors in `[0.0, 1.0]`:
- `likelihood`
- `impact`
- `exposure`
- `privilege_sensitivity`
- `data_criticality`
- `exploitability`

## Weights
The weighted scoring model is:

```text
risk_score =
  0.25 * likelihood +
  0.20 * impact +
  0.15 * exposure +
  0.15 * privilege_sensitivity +
  0.15 * data_criticality +
  0.10 * exploitability
```

Weight rationale:
- likelihood + impact dominate prioritization
- exposure and privilege/contextual sensitivity remain significant
- exploitability influences ranking but does not dominate

## Normalization and bounds
- each factor is constrained to `[0.0, 1.0]`
- weighted sum is clamped/validated in `[0.0, 1.0]`
- identical inputs must produce identical risk outputs

## Priority bands
- `critical`: `0.85 - 1.00`
- `high`: `0.65 - 0.84`
- `medium`: `0.40 - 0.64`
- `low`: `< 0.40`

## Explainability requirements
Each risk record must include:
- a plain-language `explanation`
- top `drivers` with weighted contribution values
- traceability back to source `threat_id` and `rule_id`

## Output contract
Risk outputs are represented as:
- `RiskRecord` in `models/schema/risk_model.py`
- `RiskReport` in `models/schema/risk_model.py`

Expected storage path (Phase 4):
- `models/outputs/risks/<model_id>_risks.json`

## Validation requirements
- `risk_count` must match number of `risks`
- all scores and contributions must remain in `[0.0, 1.0]`
- priority value must match defined priority bands

## Notes
- PR A (`#10`) defines methodology and schema only.
- PR B (`#11`) will implement the deterministic scoring engine and output generation.
